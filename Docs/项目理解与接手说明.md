# DONGBA 项目理解与接手说明

更新：2026-10-27，对应当前 Ecology-19。先看这份了解原型，再看代码；历史日志不是现行规则表。

## 我们现在做的是什么

项目的核心是“一幅可以走进去的象形文字森林”：人物、动物和植物由字形直接呈现，玩家的行为改变这片环境。古纸是地面与画面的底色，字形以直立的二维形态放在斜俯视空间里。不要把它理解成普通森林套上一张纸纹，也不要把文字堆成写实物体轮廓。

项目整体希望结合东巴文字、纳西神话和 XR 文化体验。Story Mode 计划让玩家参与故事，Sandbox Mode 强调自由探索和生态互动；Main View 是当前斜俯视森林，Diorama View 是团队探索的盒景表现。XR 是项目打算实现的核心方向，但**本次上传的森林模块仍是 PC 原型，不是已经完成的移动端 AR 或双视角整合**。

目前先验证“探索—互动—环境回应”是否成立。完整故事章节、剧情解谜、XR 接入和视角整合不能仅凭这份原型认定已完成。

## 先玩明白这几个动作

| 动作 | 当前结果 |
| --- | --- |
| WASD / 方向键 | 在林地移动，相机跟随 |
| Space | 跳跃；河流有阻挡，需结合当前位置与跳跃跨越 |
| J / Enter | 挥斧；砍倒树留下树桩，动物受攻击后反击 |
| E 靠近活树 | 在周围培育小植物，每棵树只能成功培育一次 |
| E 靠近树桩 | 原地补种，树从较小状态恢复；不重置已经消耗的培育机会 |
| E 靠近成年动物 | 附近有空间且未达到数量上限时，生出同种幼兽 |
| E 靠近幼兽 | 喂养两次，经过中间阶段长到成年；不会仅靠等待自动长大 |
| R | 恢复玩家位置和血量，不是重置整个生态世界 |

交互取附近对象，界面会显示当前目标。喂养有冷却，周边拥挤也可能无法出生，不是每按一次 E 都一定成功。动物总数上限当前为 64，开局约 24；不要再改回 24，否则一开始就不能繁殖。

## 生态计分：哪些行为真正改变环境

全局净值 `Balance = careCount - damageCount`。这是当前原型的统一生态依据，不要给新效果另建一套独立分数。

| 事件 | 净值变化 |
| --- | --- |
| 一棵树成功培育一次 | +1；周围长出多株植物也只算一次 |
| 树桩补种成功 | +1 |
| 幼兽从中间阶段长到成年 | +1，仅成年这一阶段计分 |
| 生出幼兽、幼兽第一次喂养成长、成年动物继续繁殖 | 0 |
| 砍倒一棵树、击杀一只动物 | 各 -1 |
| 空挥、未致命命中、攻击已死亡对象 | 0 |
| 动物亲近、跟随、迁出、返回；脚下生花 | 0 |

因此“繁殖一次”不等于“环境立刻 +1”。玩家需要把幼兽养大，才能获得动物部分的正向反馈。

## 三种状态怎么看

正常时是暖米纸底、深褐墨线，动物自由活动。树下的绿色墨晕用于表示植物丛范围，是视觉提示，不是交互距离或碰撞范围。

正向净值增加时，植物已有的绿色从根部逐步向上；花路从净值 1 开始出现，1～6 逐步变清晰，超过 6 后增加密度。花仅在人物地面移动时生成，停止或腾空时不新增，不永久留在地面。

净值达到 10 后进入繁盛反馈，附近部分成年动物可以主动亲近。当前默认最多 3 只，净值达到 16 后最多 4 只；选择范围约 11 世界单位。它们靠近后短暂陪伴、跟随，约 20～26 秒结束，不会召集整张地图，也不会永久跟随。受阻可能等待或退出，被攻击会立即中止亲近。

净值低于 0 开始衰败，约 -10 达到完整衰败程度：叶片按原有分层脱落，纸底逐步转灰米色，河流褪蓝，树下绿色转为很淡的中性色；动物逐步迁出。砍倒的树，其底斑约 1.4 秒淡出。恢复后颜色和叶片恢复，动物逐步返回。

状态过渡有平滑处理。动物亲近另有约 2 秒确认与退出阈值：净值降到 7 或以下才退出，避免在 10 附近反复切换。花路、植物转绿、动物亲近不是同一个瞬时开关。

Ecology-19 已停用横向飘过的风字，没有替代风效；原素材仍留存。不要误把素材文件仍在解释为运行时仍启用。UI 不受环境染色，衰败不是给整幅画叠灰雾。

## 打开后场景很空，是不是没导入成功

不一定。当前森林主要在运行时由代码创建，不是全部预先摆在 Hierarchy 中。打开 `Assets/DongbaPrototype/ObliqueForest.unity` 后要点击 Play，才能看到完整森林。

地图约 90×42 世界单位，游玩镜头只覆盖一部分。树丛、小植物和动物都是独立对象；不要为了方便合并成整张背景，否则砍树、照料、遮挡和生态变化会失效。

| 要改的内容 | 主要文件 |

| 字典素材加载、动植物创建、物种尺寸 | ObliqueForest.DictionaryArt.cs |

| 树下墨晕创建、砍倒后的淡出 | ObliqueForest.TreeGroundRange.cs |
| 纸纹色调 | Resources/EcologyPaper.shader |
| 树下墨晕颜色与边缘 | Resources/TreeGroundRange.shader |

这些 ObliqueForest 文件是同一个 `partial` 类的拆分，共享状态。修改一个文件时，仍要检查其他文件对同一字段的使用。旧 ForestPrototype 系列属于横版历史实现，修改错入口可能导致源码变了而当前场景没有变化。

## 素材不能随意改

字典提取素材、用户提供字形和游戏状态分层要区分。不能为了好看自行补笔画或创造字义；不能把树木受损后的残缺形态称为新的真实东巴字。

`Resources/DictionaryArt` 是字典运行素材与 catalog，`EcologyTreeV2` 是骨架、叶片及脱落碎片，`ApprovedArt` 中包含角色、花等运行图像。目录名 ApprovedArt 表示项目选用，不代表字义与版权已获得权威确认。

不要直接移动 Resources 中的路径：代码通过字符串加载，随意改名会导致缺图。替换素材时保留透明背景、长宽比例、脚底/树根锚点；提交图片必须一起提交 .meta。

现有来源说明在 Documentation/ArtSources，仍需继续补齐字典页码、授权和用户提供素材的来源记录。大体积扫描书、PPT 和源视频放资料库，不直接塞进运行工程。

## 协作与验证的边界

正式编辑仓库为 DongbaCulture_Project；E:/dongba 是本机旧工程与资料保留区。队友无需建立相同盘符。使用 README 中的 Current Forest 菜单，避免 Legacy 菜单重新生成并覆盖场景。

代码已经上传独立分支 `chore/forest-collaboration-20261027`，尚未合并 main。GitHub Desktop 先 Fetch，再切到该分支；只打开 main 看不到这些新内容。

团队项目指定 Unity **6000.3.12f1**。本机现有预览构建在独立副本中使用 **6000.3.0b1** 验证，不能代替团队版本兼容性验证。合并前需用团队版本打开、Play 并构建一次。

自动化色调对照会直接切换生态计数，并临时固定动物位置以保持相同布局；亲近演示也会设置测试生态值。这些只在指定预览参数启用，正常游戏不冻结。录像的固定模拟帧率不等同于真实性能测量。

最近实机检查覆盖了出生、成长、成年计分、再繁殖、砍树、补种，以及风字为零和树下底斑淡出。更复杂地形中的动物路径、长时间高密度繁殖、不同设备与团队版本仍需持续验证。

最小接手检查：打开森林 → 移动跳跃 → 砍树补种 → 喂出幼兽并养大 → 检查成年只加一次 → 查看繁盛亲近和衰败恢复。新增功能前先跑通这条线，避免把原有反馈改断。
